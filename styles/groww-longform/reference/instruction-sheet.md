**§2 The Visual & Data Editing Framework**

+----------------------------------------------------------------------+
| **This is a very, very important framework**                         |
|                                                                      |
| Do not underestimate the absolute necessity of this workflow.        |
|                                                                      |
| Every reference video in §12 has strictly followed this exact        |
| framework. Do a deep frame-by-frame analysis of them and you will    |
| see text, tables and source attributions integrated seamlessly with  |
| motion graphics while the creator speaks, with data dissected to     |
| maintain visual pacing. You are expected to mirror that exact level  |
| of execution.                                                        |
+----------------------------------------------------------------------+

Every Groww script is two documents in one. One is the dialogue the
creator performs. The other is a body of reference material --- tables,
colour screenshots, black-boundary screenshots, charts, data points,
source lines and special markers --- that is never spoken aloud and
exists solely so that you, the editor, put it on screen. This section
governs that second document, and it outranks creative preference
everywhere it applies.

**2.1 The Unspoken Rule**

-   The creator will only ever voice the main dialogue. They will not
    vocalise or mention the tables, the data screenshots or the sources.

-   Those elements are placed in the script strictly for you, the
    editor, to include visually.

-   **Silence about an element is not permission to drop it.** It is the
    instruction to show it. If a visual is not referred to anywhere in
    the spoken lines, that is the normal case, not an exception.

**2.2 Mandatory inclusion of visual references**

-   **Never omit any table, screenshot or data point provided in the
    script.** Not one.

-   Scripts carry reference pictures, colour screenshots, black-boundary
    screenshots, tables, and data points such as framework diagrams and
    thematic charts. All of them are in scope.

-   Before an edit is called finished, inventory every visual asset in
    the script and tick each one off against a frame in the timeline. A
    missing asset is a failed edit, not a trim.

**2.3 Absolute data accuracy**

-   **Depicting the data exactly as it is presented in the script is
    very, very important.** No factual errors, no misrepresentation.

-   No rounding, re-ordering, re-labelling, unit-changing or tidying up
    of any figure. Every number, percentage, ratio, rank, date and
    period is carried across character for character as the script wrote
    it.

-   A figure like 18.36 is not 18.4. A negative like −17.08% is not
    −17%. A rupee figure in crore is written the way the script writes
    it.

-   Where the script places a value next to a category average or a
    benchmark, all of those columns go on screen together. Never show a
    fund\'s number stripped of the comparison the script set beside it.

-   Where the script states an as-of date for the data, that date goes
    on screen with it.

**2.4 Charts, curves and candlesticks**

Some scripts carry a candlestick chart, a line graph, a bar chart or a
returns plot. These are data, not decoration, and they are the easiest
thing in the whole edit to get quietly wrong --- a chart can look right
and be wrong.

-   **Reproduce the curve exactly.** Every peak, trough, crossover and
    inflection sits where the source puts it. Do not smooth, straighten,
    simplify or otherwise improve the shape of a line.

-   **Candlesticks are read body by body.** Open, high, low and close on
    every candle must match the source, and so must the colour
    convention that marks up from down. A candle drawn the wrong way
    round inverts the meaning of the frame.

-   **Keep the axes honest.** Same scale, same range, same baseline,
    same tick values as the source. Never crop or rescale an axis to
    make a movement look larger or smaller than it actually is.

-   Keep the legend, the series colours and the series order exactly as
    the source has them, so the fund, the benchmark and the category
    stay distinguishable and are never swapped for one another.

-   Where a chart plots multiple series, every series in the source is
    drawn. Dropping the benchmark or the category line to reduce clutter
    is a data error, not a design decision.

-   Carry the period the chart covers, its axis labels and its source
    line, exactly as §2.5 requires for any other visual.

-   **If you rebuild the chart as motion graphics** instead of showing
    the screenshot, it must plot the same values and land on the same
    shape. Animate the draw-on; never redraw the data.

-   **Verify before it ships.** Put the rendered chart next to the
    source image and check the shape point by point, not at a glance.
    This is one of the pieces the critic in §14 should be judging blind
    against the source.

**2.5 Source attribution is mandatory**

-   **Whenever a reference picture or screenshot is provided, the source
    text goes visibly below it in the final edit.** Missing a source
    attribution is a critical error.

-   Reproduce the source line exactly as the script writes it, including
    any date qualifier attached to it.

-   The source stays on screen for as long as the visual it belongs to,
    and it stays legible at the final delivery resolution.

-   If a single frame carries two visuals from different sources, each
    one carries its own source line.

**2.6 Specific text callouts**

-   Special markers must be explicitly displayed. A star marker such as
    "\* Direct Growth" under a table is put on screen, never dropped as
    clutter.

-   Bold labels in the script that name which fund a screenshot belongs
    to go on screen together with that screenshot, so the viewer always
    knows whose number they are looking at.

-   **The rule is simple:** if the script marks something, the mark
    reaches the screen.

**2.7 Precise timing**

-   **Exhibit the relevant data and screenshots at the exact moment the
    creator is speaking about that specific topic.** Not before it, not
    after it.

-   Anchor each asset to its trigger line in the voice-over, and hold it
    for that passage of dialogue.

-   When the creator moves to the next metric, the previous visual moves
    off. A stale visual over new dialogue is a timing error.

**2.8 Data dissection and continuous visual movement**

-   **The video must have continuous visual movement.** Do not hold on a
    single static frame or visual for too long.

-   If the creator talks about a specific data point for an extended
    period, dissect that single data point into multiple dynamic visual
    steps --- reveal one row at a time, isolate and enlarge the figure
    under discussion, bring the comparison column in second, animate a
    bar or a pie up to its value, then step to the next line.

-   **Dissection changes the pacing, never the numbers.** Even when
    broken down, the data must remain perfectly accurate to the source.

-   A screenshot that sits motionless for the length of a spoken
    paragraph is a defect, even if the data on it is correct.

**2.9 Motion graphics integration**

-   **Heavily utilise motion graphics** to animate these tables,
    screenshots and data points, so the screen stays dynamic and
    engaging throughout.

-   This is precisely what frame types 2, 5 and 6 (§11) exist for ---
    the data-carrying frames.

-   Build the motion with emilkowalski-motion and audit the result with
    impeccable, as set out in §3.6.

**Asset types, and what has to reach the screen**

  ------------------------------------------- --------------------------------------------------------------------------------------------------------------------------------------------------------------------------
  **Asset in the script**                     **What must reach the screen**
  **Bordered data screenshot**                The full panel, revealed row by row rather than cut to whole. Fund label above it, source line beneath it.
  **Colour deck slide from an AMC**           The slide, with each column, pillar or letter revealed in step with the line being spoken. Source and any as-of date beneath.
  **Plain black-bordered comparison table**   Every column the script printed, including benchmark and category average. Star marker and source beneath.
  **Bordered prose box**                      The box, with the specific figures the creator speaks pulled out and emphasised at the moment they are said.
  **Photo-grid screenshot**                   The grid, cards animating in rather than appearing at once. Source beneath.
  **Chart or graph screenshot**               The chart, with bars or lines animating on, every series drawn, axes and legend unchanged from the source, legible at delivery resolution, source beneath (§2.4).
  **Candlestick or line chart**               The curve reproduced point for point --- every peak, trough and crossover where the source puts it, candle bodies and up/down colours exact, axes never rescaled (§2.4).
  ------------------------------------------- --------------------------------------------------------------------------------------------------------------------------------------------------------------------------

**The finished-edit checklist**

Run this before the edit is called done. Any unticked line is a failed
edit, not a note for later.

-   Every table in the script is on screen.

-   Every screenshot and reference picture in the script is on screen.

-   Every data point is on screen and matches the script character for
    character.

-   Every chart matches the source curve for curve --- peaks, troughs,
    candle bodies, axes, legend and series order all unchanged.

-   Every visual carries its source line, visibly, beneath it.

-   Every star marker and every fund label the script printed is
    displayed.

-   Every asset lands on the exact line of dialogue it belongs to.

-   Nothing holds still long enough to read as a static frame.

**§3 Brand and design system**

**3.1 Typography**

-   Two typefaces, always mixed inside the same text block: Ivy Presto
    (serif) and Inter Tight (sans serif).

-   The serif carries the emphasised half of the line; the sans carries
    the neutral half. Never set a title in one family alone.

-   Text animates in word by word, in brand purple, with a right-to-left
    in-animation.

-   **Read "right to left" precisely:** the words do not fly in from the
    extreme right edge of the frame. Each word appears in its own final
    position, with that directional animation applied in place.

**3.2 Colour**

-   Brand purple is the primary. It carries the text animation, the
    strokes, the callout boxes and the chart fills.

-   Every colour in the video carries a subtle white gradient. Nothing
    is laid down flat.

-   Charts use company colours with a highlight colour for the segment
    being spoken about, and the pie fill itself is a subtle gradient.

-   Light leaks, when used on a transition, are in the brand\'s primary
    colour.

**3.3 Backgrounds**

-   Creator-less frames: a subtle grid background with a
    white-to-brand-purple gradient. The same background is reused for
    every such scene.

-   Creator frames: a generated background. Its placement is a conscious
    decision, not a default --- it is built and positioned so that when
    text or graphics appear over it, they pop with clean visibility and
    contrast.

-   A blur gradient sits behind on-screen text. It merges rather than
    sits on top, because it is matched to the background underneath it.

**3.4 Depth and finish**

-   Circles, fund icons and cards all carry a stroke to create depth.
    Motion on the stroke is preferred --- it reads as more visually
    engaging than a static one.

-   A subtle black gradient with a nicely feathered edge sits over the
    creator. Layer order matters: the gradient is in front of the
    creator and behind the text and illustrations.

-   B-roll is enhanced with a subtle dust or texture pass. It applies to
    both AI-generated and real footage.

-   Callout boxes are never plain. They carry an internal design and a
    subtle gradient of their own.

**3.5 Tooling**

-   Motion graphics and illustration: Higgsfield, Remotion or Envato ---
    whichever serves the purpose for that shot.

-   Real footage B-roll: Envato.

-   AI-generated B-roll: Higgsfield or the Kie AI MCP.

-   **Green-screen keying and background compositing:**
    corridorkey-green-screen and ffmpeg-chromakey. Full detail in §4.

-   **Motion craft and design discipline:** emilkowalski-motion and
    impeccable. Full detail in §3.6.

**3.6 Motion craft --- the two skills that raise it**

Everything above says what moves. These two skills govern how well it
moves. Install both and run them over every motion pass --- they are
what separates a frame that animates from a frame that feels designed.

**emilkowalski-motion**

-   Motion design distilled from Emil Kowalski\'s published animation
    work. Use it after a frame is laid out, to add the entrances, state
    changes and reveals that make it feel alive without turning it into
    a motion demo.

-   **Restraint is the point.** The skill\'s discipline is what carries
    into video: transform and opacity as the primary properties, roughly
    140--220 ms for a small element\'s entrance, and one consistent
    easing language across the whole video rather than a different curve
    per shot.

-   Those figures are the skill\'s defaults for interface controls ---
    read them as the easing discipline for on-screen element entrances,
    and scale the duration to the shot, never the curve.

**§4 Plate preparation --- keying the creator and generating the
background**

The creator is shot on a green screen. Every creator frame in this sheet
--- frame types 1, 2 and 3 --- begins as a keyed plate composited onto a
generated background. The "generated background" referred to throughout
§3.3 is produced at this stage. Nothing downstream can be judged until
the key is clean, so this runs first.

+----------------------------------------------------------------------+
| **Two skills do this work --- install both**                         |
|                                                                      |
| corridorkey-green-screen --- the primary keyer, for anything         |
| reaching the final cut.                                              |
|                                                                      |
| ffmpeg-chromakey --- the fast path: previews, batch passes, spill    |
| suppression and colour work.                                         |
+----------------------------------------------------------------------+

**4.1 Remove the green screen**

-   **corridorkey-green-screen --- use this on every creator plate.** It
    solves the unmixing problem: rather than cutting a matte, it
    separates the foreground from the green plate and predicts the true,
    un-multiplied colour of the foreground alongside a clean linear
    alpha. That is what keeps loose hair strands and the patterned
    jacket edge intact instead of chewing them into a hard outline.

-   **ffmpeg-chromakey --- the fast path and the fallback.** Use it for
    quick keys, batch passes over many clips, spill suppression, and the
    colour work that sits on top of a key.

-   **Rule of thumb:** corridorkey-green-screen for every frame that
    reaches the final cut; ffmpeg-chromakey for previews, for the sample
    stills at the approval gate (§13), and for clean-up passes layered
    over a Corridor key.

**4.2 Kill the spill before compositing**

-   Green spill on hair, shoulders and the jacket edge is the giveaway
    that a frame was keyed. Suppress it as part of the key, not as a fix
    afterwards.

-   Test the edge against both a bright background and a dark one. If it
    glows green on either, the key is not finished.

-   Do not erode the matte to hide spill. That eats the hair detail the
    Corridor key exists to preserve.

**4.3 Put in the generated background**

-   Composite the keyed creator onto a generated background, built as
    described in §3.3 --- its placement is a conscious decision,
    positioned so that when text and graphics land on top, they pop with
    clean visibility and contrast.

-   Match the plate to the background: colour temperature, black level,
    and grain all have to agree, or the composite reads as a cut-out
    pasted on.

-   Hold continuity --- the same background family runs across the whole
    video, exactly as the grid background does for the creator-less
    frames.

-   The subtle black gradient from §3.4 goes on after the composite: in
    front of the creator, behind the text and illustrations.

-   The logo lock-up sits on top of the finished composite, never
    underneath it.

**4.4 Deliverable format**

-   Export keyed plates with a straight, un-premultiplied alpha --- PNG
    with alpha, ProRes 4444, or EXR --- so the compositing stage still
    has real edge data to work with.

-   Keep the un-keyed original. Every re-key comes off the source plate,
    never off a previous export.

**10.2 Grill first --- reach complete context before anything else**

+----------------------------------------------------------------------+
| **Run /grill-me before any other step**                              |
|                                                                      |
| Nothing is built off an assumption. Before the audit, before the     |
| key, before a single still is rendered, run /grill-me and let it     |
| interview you until it has the whole picture.                        |
+----------------------------------------------------------------------+

**How the session works:**

-   It maps the job as a design tree and works it in rounds. Each round
    it asks every question whose prerequisites are already settled ---
    numbered, each with its recommended answer --- and then waits for
    you.

-   Finding facts is the agent\'s job, never yours. If a question can be
    answered by reading the script, the factsheet, the reference video
    or the brand assets, it goes and finds the answer instead of asking
    you for it.

-   The decisions are yours. Every one is put to you, and it waits.

-   Your answers reshape the tree --- settled decisions push the
    frontier outward and unblock the questions that depended on them.

-   **The session ends only when the frontier is empty:** every branch
    visited, nothing silently assumed. It does not act on any of it
    until you confirm you have reached a shared understanding.

**It must have all of this nailed down before it moves on:**

-   Which funds are being compared, which factsheet dates apply, and
    which source is cited for each number on screen.

-   Where in the script the instruction section ends and the main video
    begins --- the exact line that triggers the default brand
    transition.

-   Every table, tabular column, graph, news element and screenshot the
    script contains, since all of them are mandatory on screen (§1).

-   Every Hinglish voice-over line that opens a sub-topic, since each
    one triggers a topic card.

-   Which assets are being supplied versus built: the disclaimer card,
    the default transition video, the creator plates, the B-roll.

-   Anything in this script that this sheet does not already cover ---
    that is exactly what grill-me exists to surface.

**10.3 What the gauntlet loop does, and why this sheet is shaped for
it**

-   **It sets a bar.** The skill refuses a vague target. The bar must be
    named, fetchable and comparable. §12 supplies three named, fetchable
    videos --- that is the bar, already prepared.

-   **It splits the work into judgeable pieces.** This sheet has already
    done the split: eight frame types (§11), plus the transitions (§9),
    plus each mandatory unit (§1), plus the key and the composite (§4)
    --- the key is its own judgeable piece, because a green-fringed edge
    loses the blind comparison on its own.

-   **It runs a builder and a separate harsh critic on each piece.** The
    critic has fresh context and never knows how hard the builder tried.

-   **It compares blind.** Our still goes next to the reference frame
    with the labels stripped, and the critic picks one. A pick, never a
    score out of ten --- scores drift upward every round.

-   **It loops until ours wins.** The exit condition is winning the
    blind comparison, or you stopping the run. Never a fixed number of
    rounds.

**10.4 The run order**

5.  Install the skills (§10.1) and open a fresh session with this sheet
    and the script attached.

6.  Run /grill-me and answer it out to an empty frontier (§10.2). Do not
    let it start work while a branch is still open.

7.  Inventory the script against §2 --- every table, screenshot, data
    point, source line and star marker, listed before any frame is
    designed. This list is what the finished edit is checked against.

8.  Audit the three reference videos in §12 frame by frame, in the way
    §5--§9 describe. Log every transition --- how it is used, its type,
    its duration and its trigger.

9.  Key the creator plates with corridorkey-green-screen and composite
    them onto the generated background (§4). Nothing else can be judged
    until the key is clean.

10. Read the script and decide which of the eight frame types (§11)
    belongs to which part of it, line by line.

11. Render sample stills for all eight frame types, off the real keyed
    composites --- not off mock-ups.

12. STOP at the approval gate (§13). Present the stills and the
    scene-to-script mapping. Do not proceed.

13. On approval, paste the prompt in §14 into a fresh session and let
    the gauntlet loop grind each piece until the critic picks ours
    blind.

**What breaks this loop**

-   **A vague bar.** The critic invents a comparison and approves
    everything. By far the most common failure --- this is why §12 names
    actual URLs.

-   **The builder judging its own work.** The critic must be a separate
    agent with fresh context.

-   **A soft critic.** Give it a binary job: which one is the real Groww
    frame, A or B.

-   **A named exit after N rounds.** The exit is winning the comparison,
    or you stopping the run.

-   **Skipping the approval gate.** §13 is a hard stop. Stills first,
    approval second, build third.

-   **A dropped table or a missing source.** The critic is comparing
    craft; it will happily approve a beautiful frame that silently lost
    a data point. §2 is checked separately, by inventory, not by taste.

-   **Starting before grill-me is finished.** A loop run on a wrong
    assumption converges beautifully on the wrong video. Empty the
    frontier first (§10.2).
